## Goal

Provide CSV/XLSX source-column data with stable indices and row numbers so AF-021 can support manual mapping for unfamiliar headers without putting business-field logic in the shared parser.

## Context Pack

- Relevant files: `src/lib/data/csv.ts`, `src/lib/data/excel.ts`, `src/lib/data/parser-utils.ts`, `src/lib/data/types.ts`, `src/lib/data/parser.test.mts`.
- Existing pattern: Typed import helpers accept `ExportColumn[]`; AF-021 needs a raw-table path before it can apply administrator-selected mappings.
- Assumptions: Source identity is a zero-based column index, not header text; repeated and unfamiliar labels must remain distinguishable.
- Unknowns: The repository has no dedicated test runner script; focused tests use Node's built-in test API and the existing ExcelJS dependency, run through ephemeral `tsx`.
- Allowed changes: Shared CSV/XLSX parser utilities, focused tests, and AF-019 verification artifacts.
- Do not touch: Import API/UI, database schema, business validation, exports, or unrelated files.

## Requirements

- Skip leading rows that are fully blank in both CSV and XLSX; use only the first nonblank row as the source-header candidate.
- Expose source columns by zero-based index and preserve raw header labels, including duplicates and blank-labelled columns.
- Expose row values by source index and preserve their original one-based source row numbers.
- Omit fully blank data rows after the source header while preserving the original row numbers of later rows.
- Do not search past a nonblank title/data row to guess that a later row is the header.
- If the file is empty, all rows are blank, or the workbook cannot be parsed, return a structural error and no rows.
- If XLSX bytes cannot be read as a workbook or the requested sheet does not exist, return an explicit file/sheet `ImportError` and `table: null`.
- Keep typed convenience imports and existing valid-header behavior compatible where possible; AF-021 owns target-field selection and validation.

## Acceptance Criteria

- [x] CSV/XLSX expose arbitrary source headers and distinguish duplicate labels by source index.
- [x] Both formats skip fully blank rows, preserve original row numbers, and do not return blank data rows.
- [x] A nonblank preamble remains the header candidate; no later row is guessed as the header.
- [x] Empty/all-blank input or unreadable XLSX bytes returns a structural error and no data rows/table.
- [x] AF-021 can use the raw-table contract without requiring template header equality in AF-019.
- [x] Existing typed imports and CSV/XLSX exports remain compatible.
- [x] Focused parser verification, `npm run typecheck`, and `npm run lint` pass.

## Implementation Notes
