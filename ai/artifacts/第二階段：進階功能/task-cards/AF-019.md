## Goal

Ensure both shared import parsers handle leading blank rows consistently and never return mapped data when the file header does not match the requested `ExportColumn[]` schema.

## Context Pack

- Relevant files: `src/lib/data/csv.ts`, `src/lib/data/excel.ts`, `src/lib/data/types.ts`, existing data utility verification scripts.
- Existing pattern: Callers provide `ExportColumn[]`; current CSV parsing assumes physical line 1 is the header, while Excel uses its first row containing string content.
- Assumptions: Header recognition is by the declared header labels, not object keys; labels are case-insensitive and may be reordered.
- Unknowns: The repository has no dedicated test runner script; use an existing verification harness or add focused dependency-free tests.
- Allowed changes: Shared CSV/XLSX parser utilities and their focused tests/verification scripts.
- Do not touch: Import API/UI, database schema, business validation, exports, or unrelated files.

## Requirements

- Skip leading rows that are fully blank in both CSV and XLSX.
- The first nonblank row must contain every expected `ExportColumn.header`; matching is case-insensitive and column order may vary.
- Do not search past a nonblank title/data row to guess that a later row is the header.
- If the file is empty, all rows are blank, or any expected header is missing, return a structural `ImportError` and an empty data array.
- Preserve source row numbers in parser errors and preserve the existing valid-header column mapping behavior.

## Acceptance Criteria

- [ ] CSV with one or more leading blank rows and a valid header parses mapped rows correctly.
- [ ] XLSX with one or more leading blank rows and a valid header parses mapped rows correctly.
- [ ] Headers match case-insensitively and can be in any order.
- [ ] A non-header first nonblank row, incomplete header, or all-blank file returns a structural error and zero parsed records.
- [ ] A malformed header cannot yield partially mapped data for downstream import.
- [ ] Existing valid CSV/XLSX imports and CSV/XLSX exports remain compatible.
- [ ] Focused parser verification, `npm run typecheck`, and `npm run lint` pass.

## Implementation Notes

- Keep header detection deterministic: skip only fully blank leading rows, then validate the first nonblank row.
- Use the same header matching rules in CSV and Excel paths.
- Keep parser-level structural validation separate from business-rule validation in AF-021.
- Avoid adding a parser dependency unless the current implementation cannot meet the contract safely.

## Verification Contract

- Unit/utility tests: CSV and XLSX fixtures for leading blanks, valid headers, reordered/case-varied headers, missing headers, non-header first row, and empty files.
- Regression checks: valid import data mappings and existing export serialization remain unchanged.
- Typecheck: `npm run typecheck`
- Lint: `npm run lint`
- Build: `npm run build` if route compilation or module boundaries are affected.
- Security review: ensure structural failures return no rows that downstream callers could import.
