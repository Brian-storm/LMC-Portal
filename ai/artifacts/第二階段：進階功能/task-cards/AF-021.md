## Architecture Plan — Pending High-Risk Approval

### API and Client State Contract

- Inspect request: `POST /api/admin/import/registrants/preview` with multipart `file` and no mapping returns source columns `{ index, header }`, up to 3 sample rows with original row numbers, and total row count.
- Mapped-preview request: the same endpoint receives multipart `file` plus JSON `mapping: [{ sourceIndex, targetField }]`; the server reparses the file, validates the mapping and all rows, then returns a capped mapped preview and errors/counts.
- Confirm request: multipart `file` plus the same mapping; the server reparses, revalidates duplicates and row rules, then creates all Users in one transaction.
- Browser state owns `File`, inspected source columns/sample, mapping selections, and mapped-preview response. Server request memory is discarded after each request; no session/importId.
- AF-028 validates source index range/integer, allowed target keys, unique source/target assignments, required targets, file type/size, ADMIN access, and all business validation. Manual mapping is allowed even when labels differ.

### Responsibility Boundaries

- AF-019: raw CSV/XLSX source-table extraction and parser tests; no business-field mapping.
- AF-027: reusable Variant C `RegistrantColumnMapper` component, localized labels, and design-system inventory registration; no fetch/API ownership.
- AF-028: stateless preview/confirm API, mapping/business validation, and atomic User creation; no UI.
- AF-021: wizard page orchestration, API calls/loading/error states, and end-to-end verification; no duplicate parser or business mapping implementation.

### Security, Privacy, and Persistence

- Retain ADMIN checks, .csv/.xlsx allowlist, and 10 MB limit on each request.
- The client mapping is untrusted; server revalidates indices, target keys, uniqueness, required mappings, and file data on preview and confirm.
- Inspection returns at most 3 raw sample rows to an ADMIN because source columns are not identified yet; after a source maps to `idDocNumber`, the UI masks that column. Do not log sample/file values.
- Preview performs no database writes. Confirmation creates new Users only; existing/intra-file conflicts fail the complete batch; transaction failures roll back without per-row catches.
- No Prisma schema or migration changes. Delete `temp-store.ts` only after every consumer is removed.
