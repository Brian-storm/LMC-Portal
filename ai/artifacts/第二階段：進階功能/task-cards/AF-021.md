## Goal

Make the registrant-profile import stateless between preview and confirmation, reject structurally mismatched files, and ensure either every User in a valid file is created or none are.

## Context Pack

- Relevant files: `src/lib/data/csv.ts`, `src/lib/data/excel.ts`, `src/lib/data/import/registrants.ts`, `src/lib/data/import/temp-store.ts`, preview/confirm API routes, import wizard, `prisma/schema.prisma`.
- Existing pattern: Shared parsers accept `ExportColumn[]`; preview currently stores validated rows in a module-level Map; confirm currently accepts an `importId`.
- Assumptions: User profile and identity-document fields are canonical on `User`; import creates new STUDENT users only; duplicate identity values are errors, not upserts.
- Unknowns: None for the approved import contract. Existing `Registrant` identity columns remain untouched and non-authoritative for this flow.
- Allowed changes: Import UI/API/service and this feature's artifacts/card. AF-019 owns the shared CSV/XLSX parser implementation; AF-021 consumes that parser contract. Remove `temp-store.ts` once no consumer remains.
- Do not touch: Prisma schema/migrations, export endpoint behavior outside correcting User identity-field sourcing, unrelated admin screens, or existing user records.

## Requirements

- Both preview and confirm accept the file as `multipart/form-data` field `file`; confirm re-uploads and reparses it. Do not use `importId`, server-side temporary storage, or a preview-session Map.
- For CSV and XLSX, skip leading fully blank rows. The first nonblank row must contain all expected template headers, case-insensitively; reordered columns are allowed. Missing/mismatched headers are structural errors and cannot be confirmed.
- Preview remains read-only. Any structural or row-level validation error blocks confirmation of the entire file.
- Revalidate on confirm, including existing DB duplicates and duplicates within the file.
- Create all users in a single Prisma transaction without catching individual DB failures inside the transaction. Any write failure rolls back the complete batch.
- Map identity-document fields to `User`; do not create Registrant/course/payment rows or overwrite existing users.
- Retain ADMIN authorization, CSV/XLSX support, 10MB limit, template download, first-20-row preview, and readable error feedback.
- Provide a downloadable CSV of validation errors with source row, field, and error message; all changed UI copy uses the en/zh-hk/zh-cn dictionaries.

## Acceptance Criteria

- [ ] CSV and XLSX with leading blank rows and valid headers preview correctly.
- [ ] Reordered headers are mapped by header name; missing or mismatched headers produce structural errors and no confirm action.
- [ ] Any invalid row blocks confirmation; there is no partial-success path.
- [ ] Confirmation re-uploads the file and performs server-side parsing and validation again.
- [ ] Existing and intra-file duplicate values block the entire file.
- [ ] A valid file creates every User in one transaction; a forced failure leaves no rows from that batch.
- [ ] User identity-document fields are the sole source of truth in this workflow; no Registrant rows are created.
- [ ] No server-side preview data or file remains after the preview request.
- [ ] Preview errors can be downloaded as CSV; changed UI copy is dictionary-driven for en, zh-hk, and zh-cn.
- [ ] Unauthorized requests and oversize/unsupported files are rejected with clear errors.
- [ ] `npm run typecheck` and `npm run lint` pass; integration tests cover commit and rollback behavior.

## Implementation Notes

- Depend on AF-019's shared parser contract: skip leading blank rows, then require the first nonblank row to be the complete template header; do not guess past a nonblank preamble/data row.
- Treat structural parser errors as fatal to preview eligibility; do not create an importable session from partially mapped rows.
- Keep the selected `File` in browser state through preview and submit it again to confirm.
- Return a row-aware or file-level transaction failure while preserving rollback; do not report partial imported counts.

- Integration tests: preview read-only behavior, ADMIN access, confirm revalidation, all-row commit, and full rollback on a forced write failure.
- E2E: valid CSV/XLSX upload → preview → confirm; malformed and invalid files do not change the database.
- Typecheck: `npm run typecheck`
- Lint: `npm run lint`

- Screenshot: valid preview, structural error, row validation error, success, and transaction failure states.
- Security: verify server-side file size/type checks, ADMIN guards, no trusted client preview payload, no persistent upload/preview storage, and no partial database writes.
