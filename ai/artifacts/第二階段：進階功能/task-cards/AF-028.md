## Goal

Provide stateless admin APIs that inspect raw source columns, validate an admin-selected mapping against a re-uploaded file, and create all eligible student Users atomically.

## Context Pack

- Relevant files: AF-019 raw parser contract, `src/lib/data/import/registrants.ts`, `src/lib/data/import/temp-store.ts`, preview/confirm API routes, Prisma `User` fields.
- Existing pattern: Preview currently stores validated rows in a process-memory Map and returns `importId`; confirm consumes that id. Confirm currently catches errors per row and updates an existing email match, conflicting with the approved stateless/all-or-nothing/new-user-only contract.
- Assumptions: ADMIN session/role checks, `.csv`/`.xlsx` allowlist, 10MB cap, `User` as identity source, and a single transaction are retained. No schema migration is needed.
- Unknowns: Final response shape follows the architecture contract below; confirm same-origin/CSRF behavior during the security review before implementation.
- Allowed changes: AF-028 preview/confirm routes, `src/lib/data/import/registrants.ts`, mapping helper and focused backend tests; remove `temp-store.ts` after confirming no other consumer.
- Do not touch: Frontend page/dictionaries (AF-021/AF-027), AF-019 parser implementation, Prisma schema/migrations, export behavior, unrelated APIs, or existing user records.

## Requirements

- Preview with `file` only inspects CSV/XLSX and returns source column indices/labels, up to 3 source rows with original row numbers, and total data row count. No storage/session is created.
- Preview with `file` plus JSON mapping `[{ sourceIndex, targetField }]` reparses the request and validates the mapping and every record before returning the capped mapped preview.
- Confirm accepts the same `file` plus mapping, reparses and revalidates it, and never trusts a browser preview/sample payload.
- Validate source indices as in-range integers; target keys against the fixed allowlist; no repeated source index or target key; all five required targets mapped once; optional targets may remain unmapped.
- Auto-match suggestions are not a trust boundary; manual mapping may map any source column to an allowed target.
- Enforce ADMIN authorization, file extension and 10MB limits on every request; return clear file/mapping/row errors with source row numbers where available.
- Preview performs no database writes and stores no file, parsed rows, mapping, or session.
- Check existing and intra-file email/ID/IA-license duplicates; conflicts invalidate the entire import.
- Confirmation creates new `User` rows only in one Prisma transaction. Do not update existing users and do not catch individual write errors inside the transaction; any failure rolls back the batch.
- Remove `importId`/`temp-store` behavior and preserve the CSV error-detail output contract.
- Never log uploaded values, sample values, identity data, or raw mapping payloads.

## Acceptance Criteria

- [ ] Inspection returns source indices, original header labels, capped samples, and original row numbers without persisting server state.
- [ ] Mapping validation rejects unknown fields, invalid indices, duplicate source assignments, duplicate targets, and missing required targets.
- [ ] Valid mapped preview validates the entire file and returns zero importable rows when structural or row errors exist.
- [ ] Preview and confirm preserve ADMIN/file checks; confirm ignores any client-supplied row values and reparses the uploaded file.
- [ ] Existing and intra-file duplicate values prevent the complete import.
- [ ] Valid confirmation creates all Users in one transaction; forced failure leaves no users from that batch.
- [ ] Existing users are never updated; no `Registrant`, course, or payment rows are created.
- [ ] No server preview Map, `importId`, or temporary-file/session storage remains.
- [ ] No Prisma schema migration is introduced.
- [ ] `npm run typecheck`, `npm run lint`, and focused parser/mapping/integration checks pass.

## Implementation Notes

- Use AF-019's raw-table parser; keep parser source extraction separate from business target mapping.
- Use an allowlisted target key type derived from `RegistrantImportRow`; normalize missing optional fields to existing empty/null business values.
- Run the transaction only after complete server-side parsing, mapping, and duplicate validation succeed.
- Keep the request stateless; each preview and confirmation receives the file and mapping again.

## Verification Contract

- Unit: valid mapping, exact auto-match suggestion, duplicate source labels by index, reused source/target, missing required target, optional target omitted, and out-of-range index.
- API/integration: unauthenticated/non-admin denial, unsupported/oversized file, inspection and mapped-preview no-write behavior, confirm revalidation, DB duplicates, intra-file duplicates, successful batch, and forced transaction rollback.
- Database tests use a dedicated local test database and unique fixtures; never run destructive verification against production or a shared user database.
- Commands: `npm run db:start` only for an isolated local test DB as needed; `npm run typecheck`; `npm run lint`; `npm run build`; focused Node test scripts via the existing `tsx` pattern.
- Security review: verify no server preview persistence, mapping bounds/allowlist, ADMIN and same-origin/CSRF boundary, no PII logs, and transaction rollback.
